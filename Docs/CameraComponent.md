# CameraComponent — конвенции и рекомендации

Документ объясняет, как работает `CameraComponent::GetViewMatrix()` в проекте, почему в реализации используется
`mat[3] = glm::vec4(position, 1.0f)`, какие соглашения по порядку умножения матриц и по размещению трансляции принимает
проект, и даёт рекомендации по управлению камерой (yaw/pitch).

## Почему `mat[3] = glm::vec4(position, 1.0f)`

- GLM по умолчанию использует column-major порядок хранения матриц. В таком представлении `glm::mat4` индексируется как
  массив из 4 векторов-столбцов `vec4`. Столбец с индексом 3 (`mat[3]`) — это столбец трансляции, т.е. он хранит
  вектор перемещения (x, y, z, 1).
- В коде проекта используется схема: сначала создаётся матрица поворота: `glm::mat4 mat = glm::mat4_cast(rotation);`,
  затем
  `mat[3] = glm::vec4(position, 1.0f);`. Результат — матрица вида [R | t] (4-й столбец — t), эквивалентная `T * R`
  для преобразования модели (перемещение затем поворот). Матрица вида (view matrix) вычисляется как обратная матрица
  мирового преобразования: `view = inverse(worldTransform)`.

## Рекомендованная реализация `GetViewMatrix()`

- Текущая реализация (корректная и используемая в проекте):

    1. glm::mat4 mat = glm::mat4(1.0f);
    2. mat = glm::mat4_cast(m_owner->GetRotation());
    3. mat[3] = glm::vec4(m_owner->GetPosition(), 1.0f);
    4. if (m_owner->GetParent()) mat = m_owner->GetParent()->GetWorldTransform() * mat;
    5. return glm::inverse(mat);

- Явный/альтернативный вариант с `glm::translate` (может быть более очевиден для читающего):

    1. glm::mat4 mat = glm::translate(glm::mat4(1.0f), m_owner->GetPosition());
    2. mat = mat * glm::mat4_cast(m_owner->GetRotation()); // translate * rotate — эквивалентно предыдущему
    3. if (m_owner->GetParent()) mat = m_owner->GetParent()->GetWorldTransform() * mat;
    4. return glm::inverse(mat);

> Замечание: важно соблюдать соглашение "model matrix = T * R * S" при использовании column-major и column vectors;
> в примерах выше используются эквивалентные представления.

## Пример использования в шейдере

- Предполагаемый порядок в вершинном шейдере:

  gl_Position = uProjection * uView * uModel * vec4(position, 1.0);

- Важно: `uView` — это матрица вида (inverse(worldTransform) камеры), `uProjection` — матрица проекции
  (например `glm::perspective`). Убедитесь, что uniforms подаются в шейдер в том же порядке и с одинаковым порядком
  хранения (column-major). GLM по умолчанию хранит column-major, и большинство OpenGL драйверов ожидают такой порядок
  при загрузке матриц через `glUniformMatrix4fv` (если не указано transpose).

## Управление камерой (yaw/pitch рекомендации)

- Рекомендуемая модель управления камерой: хранить yaw и pitch (в радианах) и строить поворот как кватернион или через
  euler angles:

    1. Ограничивать pitch в пределах [-89°, +89°] (или ближе к ±89 градусов), чтобы избежать переворачивания (gimbal
       lock)
       и инверсии up-вектора.
    2. yaw можно не ограничивать (круговой поворот).
    3. Для вычисления ориентации можно использовать либо кватернионы, либо вычислять forward напрямую:

        - forward = normalize(vec3(cos(pitch)*cos(yaw), sin(pitch), cos(pitch)*sin(yaw)));
        - rotation = glm::quatLookAt(normalize(forward), glm::vec3(0.0f, 1.0f, 0.0f));

    4. Альтернативно, можно строить view через `glm::lookAt(position, position + forward, up)`.

- Рекомендации по чувствительности/дельте мыши: вращение на основе delta мыши не должно умножаться на deltaTime
  (обычно вращение мышью — независимое от FPS); масштабировать дельту через `sensitivity` коэффициент.

## Простые проверки / тесты

- Тест 1 (инвариант): если камера стоит в начале координат, без вращения, `GetViewMatrix()` должно вернуть
  `glm::mat4(1.0f)`-
  инвертированную: inverse(translate(0) * rotate(identity)) = identity.
- Тест 2 (сдвиг на (0,0,2)): поместите камеру в (0,0,2) без поворота — view должен переместить сцену на -2 по Z, т.е.
  проверяйте что применение view к вектору [0,0,2,1] приводит к [0,0,0,1].
- Тест 3 (сравнение альтернатив): сравнить результат реализации через `mat[3] = vec4(pos,1)` и
  `glm::translate(...) * glm::mat4_cast(...)` — они должны совпадать (на одинаковых входных данных и при одинаковой
  политике умножения).

## Примечания

- Если в проекте используются другие конвенции (row-major, row-vectors), следует явно документировать это и
  преобразовывать матрицы при передаче их в шейдеры.
- Если будут добавлены дополнительные компоненты (например, parent scaling), убедитесь, что порядок T * R * S
  соблюдается повсеместно.
